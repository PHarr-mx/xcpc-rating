# 管理员操作手册

> 适用对象：角色为 `admin` 的 Web 管理员。  
> 本文按当前 Web 已实现功能编写，供管理员操作与功能验收使用。普通用户流程见 [普通用户操作手册.md](普通用户操作手册.md)。

---

## 1. 启动、登录与权限

### 1.1 启动服务

若服务尚未启动：

```bash
cd xcpc_web
../.venv/bin/reflex run
```

浏览器访问 `http://localhost:3000/`。环境安装、端口和数据库说明见 [启动指南.md](启动指南.md)。

### 1.2 创建首个管理员

注册页面创建的用户默认都是 `member`。首个管理员通过项目命令创建：

```bash
cd xcpc_web
../.venv/bin/python create_admin.py --username admin --password 你的密码
```

随后使用该账号在 `http://localhost:3000/login` 登录。

忘记密码时，用 `--reset-password` 重置已有用户密码（会使其既有会话失效；用户不存在则报错）：

```bash
cd xcpc_web
../.venv/bin/python create_admin.py --username admin --password 新密码 --reset-password
```

### 1.3 管理员可访问的页面

| 路径 | 页面 | 用途 |
|---|---|---|
| `/admin` | 后台概览 | 查看统计和进入各后台模块 |
| `/admin/users` | 用户与绑定审批 | 批准 / 驳回选手绑定申请，查看用户 |
| `/admin/players` | 选手管理 | 新建、编辑、入队、标记退役、标记离队 |
| `/admin/teams` | 队伍管理 | 新建队伍、追加别名、删除队伍 |
| `/admin/contests` | 比赛管理 | 搜索、筛选、删除比赛 |
| `/admin/audit` | 审计日志 | 查看后台写操作记录 |
| `/admin/import` | 在线正式赛导入 | 上传、预览、匹配并确认导入 xlsx |

登录后的管理员导航栏显示“后台概览”“选手管理”“队伍管理”“比赛管理”“审计日志”。**“在线正式赛导入”不在顶部导航栏中**，请从 `/admin` 的快捷按钮进入，或直接访问 `/admin/import`。

> 非管理员账号访问 `/admin/*` 会被阻止并重定向；请勿以普通账号验收后台写操作。

## 2. 后台概览：`/admin`

### 操作步骤与预期

1. 访问 `http://localhost:3000/admin`。
2. 确认页面标题为 **“后台概览”**。
3. 检查三个统计卡：
   - **待审批绑定**；
   - **用户数**；
   - **已绑定**。
4. 点击快捷入口，确认可分别进入：
   - 前往绑定审批；
   - 前往选手管理；
   - 前往队伍管理；
   - 前往比赛管理；
   - 查看审计日志；
   - 在线导入正式赛。

“待审批绑定”统计卡本身也可以进入绑定审批页。

## 3. 用户与绑定审批：`/admin/users`

此页面包含“待审批绑定”和“用户”两个列表。用户列表为只读；绑定申请可批准或驳回。

### 3.1 批准绑定申请

建议先按照普通用户手册，用一个测试账号提交针对测试选手的绑定申请。

1. 管理员访问 `/admin/users`。
2. 在 **“待审批绑定”** 表中核对：申请人、目标选手、说明、申请时间。
3. 确认申请人与选手身份无误后，点击该行 **“批准”**。
4. 检查页面绿色提示，例如：

   ```text
   已批准绑定：p001
   ```

5. 使用申请人的普通账号重新打开或刷新 `/profile`。

**预期结果：**

- 该申请从待审批列表中消失；
- 普通用户看到“绑定信息”和“自助资料”；
- 用户列表的“绑定选手”列显示对应选手；
- 审计日志中会生成 `binding.approve` 记录。

### 3.2 驳回绑定申请

1. 在待审批列表中选择一条测试申请。
2. 点击 **“驳回”**。
3. 检查绿色提示，例如：

   ```text
   已驳回申请：p001
   ```

**预期结果：**

- 申请从待审批列表中消失；
- 用户未获得选手绑定；
- 用户可以重新提交申请；
- 审计日志中会生成 `binding.reject` 记录。

### 重要规则

- 一个选手只能绑定一个用户；一个用户只能绑定一个选手。
- 批准某用户的一条申请时，该用户其他仍待审批的申请会自动驳回。
- 若申请在处理前已被其他管理员处理，页面会提示“该申请已被处理，请刷新页面”。

## 4. 选手管理：`/admin/players`

### 4.1 列表与筛选

页面可按以下条件筛选：

- 搜索：选手 ID、姓名、Handle、别名或 OJ 账号；
- 状态：`all`、`active`、`retired`、`left`；
- 年级：输入入学年。

页面同时显示“现役”“退役”“离队”的当前筛选结果计数。表格包含 ID、姓名、Handle、年级、状态、别名、OJ 账号和操作。

### 4.2 新建选手

1. 点击 **“新建选手”**。
2. 在弹窗中填写：

   | 字段 | 要求 / 示例 |
   |---|---|
   | ID | 可留空自动生成，例如 `p025`；也可填写未被占用的 ID |
   | 姓名 | **必填** |
   | 校内简称 / Handle | 可选 |
   | 入学年 | 可选；留空表示未设置 |
   | 状态 | `active`、`retired` 或 `left` |
   | 别名 | 每行一个，或用逗号分隔 |
   | OJ 账号 | 每行一条，格式 `平台:账号`，例如 `codeforces:tourist` |

3. 点击 **“保存”**。
4. 在表格中搜索刚创建的 ID 或姓名。

**预期结果：**出现绿色“已创建选手”提示，表格中出现新记录，审计日志产生 `player.create`。

### 4.3 编辑选手

1. 在目标选手行点击 **“编辑”**。
2. 修改允许字段。
3. 点击 **“保存”**。
4. 重新搜索或刷新列表，确认展示内容更新。

**预期结果：**出现“已更新选手”提示，审计日志产生 `player.update`。

### 4.4 入队（预备队员 → 现役）

1. 在状态筛选中选择 `probation`，找到预备队员。
2. 点击 **“入队”**。
3. 确认状态筛选切回 `active` 后能搜到该选手。

**预期结果：**选手状态从“预备队员”（蓝色徽章）变为“现役”（绿色徽章），审计日志产生 `player.update`。

> 招新流程：通过招新考试的选手由管理员以 `probation` 状态新建（或编辑现有选手状态）；通过入队考核后点“入队”转为现役。只有预备队员可以入队，退役/离队选手不能借“入队”复活。

### 4.5 标记退役

1. 找到状态为 `active` 的测试选手。
2. 点击 **“标记退役”**。
3. 在状态筛选中选择 `retired`，搜索该选手。

**预期结果：**选手状态变为 `retired`（徽章为橙色），操作列仍显示“标记离队”。退役选手**保留在榜单中**（榜单只排除 `left`），档案与历史 Rating 不变；审计日志产生 `player.update`。

> “标记退役”是状态变更，不是删除；适合选手毕业、转为教练等不再参赛但档案继续展示的场景。

### 4.6 标记离队（软删除）

1. 找到状态不是 `left` 的测试选手。
2. 点击 **“标记离队”**。
3. 在状态筛选中选择 `left`，搜索该选手。

**预期结果：**选手仍保留在数据库和列表中，但状态变为 `left`，操作列显示“已离队”。历史记录不会被删除。

> “标记离队”是**软删除**，不是物理删除；当前审计动作名为 `player.delete`。离队选手不再出现在榜单中。

### 异常与注意事项

- 姓名为空、年级不是数字、状态无效、OJ 账号格式错误或核心数据校验失败时，页面会显示红色总提示和字段级提示；修正后重新保存。
- 删除 / 标记离队测试应使用专门的测试选手，不要对生产选手执行。

## 5. 队伍管理：`/admin/teams`

### 5.1 核心业务规则（必须遵守）

> **队伍身份由成员集合决定，不由队名决定。**
>
> 成员相同的队伍只能有一个，即使队名不同也应视为同一队伍并添加别名；成员发生变化时，必须新建队伍，不能编辑原队伍成员。

页面的 `member_key` 是成员 ID 排序后的组合，例如 `p001|p002|p003`，可用于核对成员集合。

### 5.2 搜索队伍

在搜索框输入队伍 ID、成员 ID、成员姓名、`member_key` 或别名。确认表格显示的成员、成员数、`member_key` 和别名与筛选条件一致。

### 5.3 新建队伍

1. 先在“选手管理”中确认各成员的 `player_id` 已存在。
2. 点击 **“新建队伍”**。
3. 填写：

   | 字段 | 要求 / 示例 |
   |---|---|
   | ID | 可留空自动生成，例如 `t009` |
   | 成员 player_id | 必填；可用逗号、中文逗号、分号、空格或换行分隔，例如 `p001,p002,p003` |
   | 队名 / 别名 | 可选；每行一个或用逗号分隔 |

4. 点击 **“保存”**。
5. 搜索新队伍 ID 或别名确认创建结果。

**预期结果：**绿色提示显示“已创建队伍”，表格出现成员集合和 `member_key`，审计日志产生 `team.create`。

### 5.4 编辑队伍别名

1. 在队伍行点击 **“编辑别名”**。
2. 注意此时 ID 和成员输入框均不可编辑。
3. 填写要追加的别名，点击 **“保存”**。

**预期结果：**绿色提示显示“已更新队伍别名”，新别名出现在表格中，审计日志产生 `team.update`。

> 编辑不会删除已有别名，只会追加当前输入中尚不存在的别名；没有新别名时会提示“队伍未修改”。

### 5.5 删除队伍

1. 搜索并确认目标是**测试队伍**。
2. 点击 **“删除”**。
3. 再次搜索该队伍 ID。

**预期结果：**出现“已删除队伍”提示，搜索无结果，审计日志产生 `team.delete`。

> 当前删除按钮会直接执行物理删除，页面没有二次确认对话框。不要删除历史或正式比赛依赖的队伍。

### 常见错误

- 输入不存在的成员 ID：页面报错，不能创建。
- 成员集合与已有队伍相同：核心唯一规则阻止创建；应改为编辑已有队伍别名。
- 要“换人”时：不能编辑原队伍成员，应新建新成员集合的队伍。

## 6. 比赛管理：`/admin/contests`

### 6.1 查看与筛选

1. 访问 `/admin/contests`。
2. 使用搜索框按比赛 ID、标题、比赛类型、赛季或来源文件筛选。
3. 使用来源下拉框选择：`all`、`formal`（正式赛）或 `training`（训练赛）。
4. 检查顶部的全部、正式赛、训练赛计数与下方当前列表对应。

表格显示比赛 ID、标题 / 类型 / 赛季、日期 / 来源、赛制、队伍统计、是否计入 Rating / 权重等信息。

### 6.2 删除比赛

1. 为验收准备一个专用的测试比赛 ID，例如：

   ```text
   manual_web_test_20260825
   ```

2. 在比赛管理中搜索该 ID。
3. 核对标题和比赛 ID 后，点击 **“删除”**。
4. 检查绿色提示，并重新搜索该 ID。
5. 前往审计日志，确认存在 `contest.delete` 记录。

**预期结果：**比赛从列表中消失。

> **高风险操作：**删除比赛会通过核心 contest API 清理该比赛的 standings（成绩）以及关联的派生 RatingEvent。当前删除按钮无二次确认，且操作不可撤销。仅对测试比赛执行。
>
> 删除比赛**不会**删除导入时新建的选手或队伍，也不会把导入当作完整回滚。

## 7. 审计日志：`/admin/audit`

此页面只读，用于核对后台写操作是否被记录。

### 操作步骤

1. 访问 `/admin/audit`。
2. 可选筛选条件：
   - **用户名或用户 ID**；
   - **动作**；
   - **开始日期**、**结束日期**（日期格式 `YYYY-MM-DD`）。
3. 检查表格中的：时间、用户、动作、目标、变更摘要。

当前动作筛选下拉框包含：

```text
all
binding.approve
binding.reject
player.create
player.update
player.delete
team.create
team.update
team.delete
contest.delete
```

### 预期结果

完成本手册中的批准 / 驳回、选手、队伍、比赛操作后，均可在这里用 `all` 或对应动作筛选定位记录。

> 在线导入确认也会记录 `import.confirm`，但该动作**当前不在动作下拉框中**。需要检查导入审计时，请保留动作筛选为 `all`，再按日期、用户或目标比赛 ID 定位。

## 8. 在线正式赛导入：`/admin/import`

该流程用于导入正式赛 Excel 文件，分为上传、填写元信息、预览、处理未匹配选手和确认五步。

### 8.1 导入前的安全准备

- 仅支持 `.xlsx` 与 `.xlsm` 文件。
- 使用来源明确、结构符合正式赛导入器要求的成绩表。
- 测试时务必使用全新的、容易识别的 `contest_id`，例如：

  ```text
  manual_web_test_20260825
  ```

- 不要使用已经存在的正式比赛 ID，以免发生更新 / 覆盖风险。
- 若文件中有无法自动匹配的选手，确认前必须人工判断其身份；不要仅按同名随意关联。

### 8.2 上传文件并填写元信息

1. 访问 `/admin/import`，确认标题为 **“在线正式赛导入”**。
2. 点击 **“选择 xlsx 文件”**，上传一个 `.xlsx` 或 `.xlsm` 文件。
3. 页面显示上传文件名后，填写：

   | 字段 | 要求 |
   |---|---|
   | `contest_id` | **必填**；建议使用唯一测试 ID |
   | 比赛日期 | **必填**；使用日期控件，格式为 `YYYY-MM-DD` |
   | `contest_type` | **必填**；默认值为 `icpc_provincial`，必须是系统权重配置可识别的类型 |
   | 默认入学年 | 可选；供本次确认中新建的未匹配选手使用 |

4. 点击 **“解析并生成预览”**。

**预期结果：**成功上传后先显示“已上传：文件名，请填写比赛元信息”。解析成功后显示“解析完成，请核对预览并处理未匹配选手”或“解析完成，可确认导入”。

### 8.3 核对解析预览

解析完成后，页面显示：

- 总队数；
- 本校队数；
- 奖牌队数；
- 未匹配选手数；
- 奖牌线说明（gold / silver / bronze 依据表格正式组奖牌或百分位推算）。

此时仅创建一条 `ImportBatch`，其状态为 `staged`；**尚未创建或修改正式的 Player、Team、Contest、Standing，也未写入 raw 归档文件。**

如预览中的队伍数、奖牌数或未匹配人数不符合预期，点击 **“取消导入”**，修正文件或元信息后重新上传和解析。

### 8.4 处理未匹配选手

若页面出现 **“步骤 4：处理未匹配选手”**：

1. 逐行核对未匹配选手姓名和所在队伍。
2. 在每行下拉框中选择：
   - `new`：确认导入时新建一个选手；或
   - 一个已有 `player_id`：把该姓名关联到已有选手。
3. 对每一条未匹配姓名均完成选择。

**预期结果：**每条未匹配选手都有决议后才能成功确认。

> 下拉选项中的 `new` 是一个实际值，表示“新建”；其余选项为现有全部选手 ID（包括状态为 `left` 的选手）。
>
> 同一未匹配姓名在该批次中只需要决议一次，该决议会应用于这个姓名出现的相关行。请先确认不是两个不同的人同名。

若存在没有决议的姓名，点击确认会显示类似“未为未匹配选手 xxx 指定处理决议”的红色错误提示，正式数据保持不变。

### 8.5 确认导入

1. 再次核对文件、`contest_id`、预览统计和所有未匹配选手的决议。
2. 点击 **“确认导入”**，不要重复点击。
3. 等待绿色结果提示。
4. 打开 `/admin/contests`，搜索本次 `contest_id`，确认比赛已出现。
5. 打开 `/admin/audit`，保持动作筛选为 `all`，确认存在 `import.confirm` 记录。

**确认成功后的预期结果：**

- 页面显示类似：

  ```text
  导入完成：比赛标题（N 支队伍）
  ```

- 写入本次需要新建的 Player；
- 写入或复用 Team；
- 写入 Contest 和 Standing；
- 将导入结果归档到 `data/raw/formal/{contest_id}.json`；
- 生成 `import.confirm` 审计记录；
- 导入批次状态变为 `confirmed`，不能再次确认或取消。

核心业务库中的正式数据写入在一个数据库事务中完成；数据库提交成功后才写 raw 归档文件。

### 8.6 取消导入

1. 在确认前点击 **“取消导入”**。
2. 检查页面绿色提示：

   ```text
   已取消导入，正式数据未发生变化
   ```

**预期结果：**当前 staged 批次变为 `discarded`，不会写入正式 Player、Team、Contest、Standing 或 raw 归档。该批次不能再次确认或取消。

### 8.7 在线导入的补充限制

- 重新上传文件会替换本页面当前的临时上传文件；确认或取消后临时文件会清理。
- 解析阶段生成的 staged 批次本身会保留于数据库中，用于确认或记录状态；它不是正式比赛数据。
- 取消或删除比赛不能自动删除本次导入创建的选手、队伍。为避免污染真实数据，建议在隔离数据库中测试，或优先关联已有的测试选手。
- 页面错误提示是最终判断依据。遇到日期、比赛类型、Excel 格式或业务唯一约束错误时，修正输入后重新执行相应步骤。
