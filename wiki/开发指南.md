# 开发指南

给开发者（含 AI Agent）的实操手册：环境怎么搭、代码怎么写、坑在哪。

---

## 1. 开发环境

```bash
source ./setup_env.sh   # uv sync + 激活 .venv（Python 3.13 由 .python-version 锁定）
```

测试（**两套分开跑**，根 `pyproject.toml` 的 `testpaths` 只含 core）：

```bash
uv run python -m pytest xcpc_core -v                    # core（在项目根目录）
cd xcpc_web && ../.venv/bin/python -m pytest tests -v   # web State 层测试
```

Web 应用：`cd xcpc_web && ../.venv/bin/reflex run`（端口 3000）。

## 2. 编码约定

### 2.1 两条硬性规则（违反就重写）

- **`xcpc_core` 绝不 `import reflex`**——业务层必须能脱离 web 运行（CLI / pytest）
- **`xcpc_web` 绝不写 SQL、不承载业务规则**——State 只做「读表单 → 调 core → 转视图模型 → 写 var」

### 2.2 CRUD 六件套（新增域对象照抄 player/team/tier 模式）

| 文件 | 职责 | 关键点 |
|------|------|--------|
| `models.py` | Pydantic DTO | Base/Create/Update/实体 + 校验器 |
| `store.py` | SQLAlchemy repository | DTO↔ORM 转换在 store 边界 |
| `service.py` | 业务逻辑 | 唯一约束、ID 生成、筛选；**写路径 bump data_version**（`db/meta.bump_data_version`，只 flush 随调用方事务提交） |
| `api.py` | **对外唯一读写入口** | CLI 与子模块都从这里导入；注入 store 时 session 由调用方管理 |
| `cli.py` | argparse 命令行 | |
| `exceptions.py` | 模块异常 + 子类 | 消息可直接展示到 UI |

### 2.3 其他约定

- **DTO 与 ORM 分离**；**唯一性下沉 DB**：service 捕 `IntegrityError` 转领域异常
- **`find_repo_root()`** 基于 `data/raw` 标志目录向上定位仓库根；测试注入临时路径
- **队伍身份由 `member_key`**（排序后队员集合）决定，与队名无关
- **每个写操作写审计**（`xcpc_core.audit.api`，best-effort）
- **列表类 computed var 一律 `cache=False`**（见 §5 坑）

## 3. 推荐开发循环

```
1. 先在 xcpc_core 用 pytest 把逻辑跑通     ← 不依赖 Reflex，快且可测
2. CLI 冒烟（如 python -m xcpc_core.player.cli list）
3. 再包 Reflex State：只做视图与交互        ← 逻辑已在 core，State 薄
4. 页面组件；私有数据走带权限的 computed var
```

合入前两套测试全绿；涉及新 UI 的还要跑一次浏览器手工验收。

## 4. 常用任务速查

| 任务 | 做法 |
|------|------|
| 导入正式赛 xlsx | Web `/admin/import`（五步）；CLI 走 `importer.import_formal_xcpcio_xlsx` |
| 导入训练赛/个人赛 | Web `/admin/import` 的 JSON 通道；CLI `python -m xcpc_core.importer.cli import x.json` |
| 补录打星队 | `importer.add_formal_team`（award 须达奖线） |
| 选手 / 队伍 CRUD | `xcpc-player` / `xcpc-team` CLI 或 `player.api` / `team.api` |
| 改赛事等级系数 | Web `/admin/tiers`（写 `tier` 表）；`contest_weights.yaml` 只是种子 |
| 改 Rating 公式参数 | Web `/admin/rating` 试算 →「应用」写 `rating_params.yaml`；或直接改 `rating/formula_params.py` 的默认值 |
| 建 / 重置 admin | `cd xcpc_web && ../.venv/bin/python create_admin.py --username u --password p [--reset-password]` |
| 批量建号 | Web `/admin/users` 批量表单 |
| 跑一次性迁移 | `uv run python -m xcpc_core.db.migrate`（幂等；schema 走 alembic） |
| 加表/加列 | 改 `tables.py` → `uv run python -m xcpc_core.db.migrations.revision -m "..."` → **人工核对脚本** → 提交 |
| 备份 DB | `sqlite3 data/db/xcpc.db ".backup <路径>"` |
| 看数据版本 | 榜单页脚 `Data Version`；写路径自动 bump |

## 5. 避坑清单

### 5.1 Reflex 相关

| 坑 | 后果 | 应对 |
|----|------|------|
| 版本不锁 | API 变化破坏代码 | 锁死 0.9.7，升级独立任务 |
| computed var `cache=True` 无 interval | **永不失效**——列表/自助字段同会话二次操作读到旧快照（连加 OJ 账号会覆盖前一个） | 列表类一律 `cache=False` |
| 预渲染泄露 | 组件树里的数据对所有人可见 | 私有数据走带权限的 computed var |
| 动态路由参数同名 state var | `DynamicRouteArgShadowsStateVarError` | 从 `self.router.page.params` 读 |
| Var 不能 iterate / `or` / `bool()` | 构建期报错 | 列表/字典视图在 State 里**预计算成 view dict** |
| Var 之间数值比较 | `TypeError: not supported between ObjectItemOperation and int` | 比较结果也在 State 预算成布尔字段 |
| Var 字符串拼接 | `unsupported operand type(s) for +` | 同上，拼好再传 |
| `rx.select` 用每行 Var 列表 | `ForeachVarError: Could not foreach over var of type Any` | 用 **State 级扁平选项列表**（如全量 ID + `new`） |
| `rx.foreach` 循环变量当字典键查 Python dict | 构建期 `TypeError` | 字段集已知时用构建期静态展开 |
| `rx.cond` 构建期两分支都求值 | `href=None` 会炸 | 用 `""` 哨兵 |
| `app` 模块改动 HMR 失效 | "No module update found" | 重启服务；`rxconfig`/主题改动**必须**重启 |
| 测试导入 app 模块 | `rx.App()` 顶层副作用破坏手工状态链（跨测试 DB 复用、UNIQUE 冲突） | **测试中禁止 import `xcpc_web.xcpc_web`** |
| 测试直读 `self.router` | router 是 Base 层继承 var，直接实例化的 State 赋值转发给不存在的 parent | 照运行时 processor：赋 `router_data` 后注入 `RouterData` |
| `auth_token` 设错层级 | `'NoneType' object has no attribute 'auth_token'` | 设在**链根**（`LocalAuthState`） |
| 页面文案写 Markdown `**` | `rx.text` 不解析，原样显示星号 | 用 `rx.text(weight="bold")` 或去掉 |

### 5.2 数据层相关

| 坑 | 后果 | 应对 |
|----|------|------|
| SQLite 只开 WAL | 仍有 `database is locked` | WAL + busy_timeout + 短事务三件套 |
| PRAGMA 只设一次 | 外键/timeout 不生效 | 挂 `connect` 事件逐连接执行 |
| 改 `tables.py` 不写迁移 | schema 漂移 | 漂移守护测试会拦下；生成后**人工核对** |
| 事务内改 `foreign_keys` | 是 no-op | 重建式迁移先 stash 数据，按「子表→父表」drop |
| 测试写真实仓库 | `data/raw/` 被污染 | `isolate_repo_root` autouse fixture 重定向 `find_repo_root` |

### 5.3 架构相关

| 坑 | 后果 | 应对 |
|----|------|------|
| facade session 不关 | 连接池耗尽（Web 点不动） | 未注入 store 时 finally 关闭；注入时调用方负责 |
| 长任务放写事务 | 锁表 | 解析/重算与落库分短事务；`@rx.event(background=True)` |
| Pydantic 塞进 state var | 序列化不稳 | `rx.Base` 视图模型中转 |
| 绕过 `*.api` 改存储 | 约束失效、缓存不失效、审计缺失 | 一律走各模块 api |
| 单进程约束被忽略 | 同一用户请求落到不同进程 | **不要加 `--workers`** |
| `api_url=localhost` | 公网只有本机能连 | 部署时配公网地址 |
| 注册事务拆开 | 「有凭据无 profile」用户 | 覆写 `_register_user` 同事务补写 UserProfile |

### 5.4 测试数据层踩坑（sqlmodel / reflex-local-auth）

| 坑 | 应对 |
|----|------|
| `s.exec(select(Model))` 返回**列元组**而非模型 | 用 `s.scalars(select(Model))` |
| `LocalUser.verify_password(...)` 不存在 | 是实例方法 `user.verify(secret)` |
| `LocalUser.hash_password` | 是 staticmethod，可类上调用 |

## 6. 与 AI Agent 协作

`skill/` 下提供 Agent 工作流（各 `SKILL.md`）：

| 技能 | 触发场景 | 要点 |
|------|----------|------|
| `formal-import` | 正式赛导入 | 收集参数 → 预览解析 → 执行 → 补录打星队 → 报告 unmatched |
| `player-manage` | 选手增删改查 | 必须走 `player.api` / CLI，勿绕过 API 改存储 |
| `team-manage` | 队伍增删改查 | 队员集合识别，队名进 aliases |

配合仓库根 **CLAUDE.md** 使用（命令、分层模式、文档索引）。给 Agent 的提示词建议包含：
目标文件与模块路径（避免靠猜）、「只读/可写」边界、测试命令、遵循的文档。

技能文件约定：每技能一个子目录一个 `SKILL.md`；禁止爬取逻辑、子串匹配等不规范操作；
CLI/API 路径随包结构同步更新。
