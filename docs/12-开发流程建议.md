## 1. 现状一句话

项目从「静态站 + JSON 数据流水线」迁移到「Reflex + SQLite」。**包结构已迁到 `xcpc_core/`、持久化已落地 SQLite**：
player/team store 已是 SQLAlchemy repository，`migrate` 已把 raw 数据灌入 `data/db/xcpc.db`。开发时先看清自己是在
「维护现有 SQLite 模块」还是「按蓝图新建模块（rating / board / contest / auth）或 xcpc_web」。

## 2. 开发环境

```bash
source ./setup_env.sh   # uv sync + 激活 .venv
```

- Python 3.13（`.python-version`，uv 受管），依赖见 `pyproject.toml`（pydantic / openpyxl / pyyaml）
- 包由安装机制解析（`xcpc_core.*`），不再有 PYTHONPATH hack
- 测试在项目根目录运行：

```bash
uv run python -m pytest xcpc_core -v
uv run python -m pytest xcpc_core/tests/test_team_crud.py -v     # 单个文件
```

## 3. 工程分层与编码约定

### 3.1 两条硬性规则（违反就重写）

- **`xcpc_core` 绝不 `import reflex`** —— 业务层必须能脱离 web 运行（CLI / pytest / 定时任务）。
- **`xcpc_web` 绝不写 SQL、不承载业务规则** —— State 只做「读表单 → 调 core → 转视图模型 → 写 var」。

### 3.2 CRUD 模块六件套（沿用现有 player/team 模式）

新增一个可 CRUD 的域对象时，照 `xcpc_core/player/` 的结构：

| 文件 | 职责 | 关键点 |
|------|------|--------|
| `models.py` | Pydantic DTO | `Base` / `Create` / `Update` / 实体 + 校验器 |
| `store.py` | 持久化 | 现在写 JSON，迁移后改 repository |
| `service.py` | 业务逻辑 | 唯一约束、ID 生成、筛选 |
| `api.py` | **对外唯一读写入口** | CLI 与子模块都从这里导入，勿直接读写 JSON |
| `cli.py` | argparse 命令行 | |
| `exceptions.py` | 模块异常 + 子类 | 供 UI 直接展示错误消息 |

### 3.3 迁移期约定

- **DTO 与 ORM 分离**：领域对象用 Pydantic，DB 层用 SQLAlchemy（`xcpc_core/db/`），显式互转（见 [10](10-数据存储与SQLite.md) §3.1）
- **唯一性下沉到 DB**：service 层捕获 `IntegrityError` 转 `PlayerValidationError`，异常语义不变
- **`find_repo_root()` 定位仓库根**：基于 `data/` 标志文件；测试用 `repo_root=tmp_path` 注入临时仓库
- 队伍身份由 `member_key`（排序后的 player_id 集合）决定，与队名无关

## 4. 推荐开发循环

```
1. 先在 xcpc_core 用 CLI / pytest 把逻辑跑通   ← 不依赖 Reflex，快且可测
2. 再包一层 Reflex State，只做视图与交互       ← 逻辑已在 core，State 薄
3. 每个改动先写测试，再写实现（TDD 节奏）
```

具体到一次功能：

1. **写测试**（`xcpc_core/tests/` 或 `xcpc_core/<模块>/tests/`），覆盖正常 + 异常路径
2. **实现 core 层函数**，通过 `api.py` 暴露
3. **CLI 冒烟**：`python -m xcpc_core.player.cli list` 等，确认可命令行驱动
4. **包 State**：事件处理器只调 core、处理异常、写 state var
5. **页面**：组件调用 State；私有数据走带权限的 computed var

> 长任务（xlsx 解析、Rating 全量重算）用 `@rx.event(background=True)`，
> 且**不放写事务里**（见 [10](10-数据存储与SQLite.md) §7.2）。

## 5. 分期实施指引

各期进入条件、产出、验收见 [13-实施路线图](13-实施路线图.md)。此处给出各期的**开发要点与坑**：

### 一期 · 地基
- **先统一包结构**（pyproject）再动别的，否则每步都在跟 PYTHONPATH 打架
- 建表开发期用 `Base.metadata.create_all`（`xcpc_core/db/session.create_all`）；schema 稳定后再引 alembic
- `migrate_from_json` 要求幂等（按主键 upsert），现有 ID 原样保留
- 完成标志：真实数据能看到榜单

### 二期 · 认证
- 三处校验点都要写，但记住只有「事件处理器 + computed var」是真防护
- `@require_login` 只处理未登录，**不认识 admin**，角色判断自己写
- 注册后在同一事务补写 `UserProfile`，避免「有凭据无 profile」
- 完成标志：权限三处校验点立稳

### 三期 · 管理后台
- 在线导入核心是 `ImportBatch`：先 staged，人工复核后才写正式表
- 未匹配项人工决策，替代 `auto_create_players=True` 盲目建号
- 完成标志：不再需要敲 CLI 导入

### 四期 · 业务补齐
- Rating 按 [06](06-Rating计算模块.md) 实现 `BaseRatingCalculator` 继承体系，MVP 用 placeholder
- 权重试算不落库、不进缓存，只在页面 diff
- 完成标志：榜单数值有业务含义

### 五期 · 上线
- 本地构建前端产物后 rsync，服务器保持干净
- `api_url` 配公网可达地址，写 `localhost` 只有本机能用
- 完成标志：公网可访问

**两条顺序约束**：一期必须最先；二期必须在三期之前（否则会先做出一批无认证的写接口）。

## 6. 常用任务速查

| 任务 | 做法 |
|------|------|
| 导入正式赛 xlsx | 见 [04](04-数据导入与加工模块.md) §4.3；CLI 或 `importer.import_formal_xcpcio_xlsx` |
| 选手 CRUD | `python -m xcpc_core.player.cli`（list/get/find/create/update/delete/mark-left） |
| 队伍 CRUD | `python -m xcpc_core.team.cli`（按 `member_key` 识别同一性） |
| 加字段 | models.py 加字段 + store/service 顺带 + 迁移 |
| 改比赛权重 | `data/config/contest_weights.yaml`；正式赛按 `contest_type`、训练赛按 `division` |
| 跑迁移 | `uv run python -m xcpc_core.db.migrate`（见 [10](10-数据存储与SQLite.md) §5） |
| 备份 DB | `sqlite3 xcpc.db ".backup <路径>"`（见 [11](11-部署与运维.md) §5） |
| 跑全部测试 | `uv run python -m pytest xcpc_core -v` |

## 8. 避坑清单

| 坑 | 后果 | 应对 |
|----|------|------|
| Reflex 版本不锁 | 升级 API 变化（`CustomComponent`→`rx.memo`） | requirements 锁死版本，升级作独立任务 |
| 预渲染泄露 | 组件树里的数据对所有人可见 | 私有数据走带权限的 computed var |
| SQLite 只开 WAL | 仍有 `database is locked` | WAL + busy_timeout + 短事务，三件套缺一不可 |
| `PRAGMA foreign_keys` 只设一次 | 外键不生效 | 挂 `connect` 事件逐连接执行 |
| 单进程约束被忽略 | 同一用户两次请求落到不同进程 | **不要加 `--workers`** |
| `api_url=localhost` | 只有本机能连 | 配公网可达地址 |
| 长任务放写事务 | 锁表 | 解析/重算与落库分成短事务 |
| Pydantic 塞进 state var | 序列化不稳 | 用 `rx.Base` 视图模型中转 |
| 改 JSON 绕过 api | 约束失效、日志缺失 | 一律走 `player.api` / `team.api` |
