# 数据导入与加工模块设计

> 关联：[DESIGN.md](DESIGN.md) · [比赛与记录](./03-比赛与记录模块.md) · [数据导出与发布](./05-数据导出与发布模块.md) · [数据存储与SQLite](./10-数据存储与SQLite.md)

> 已采纳 Reflex + SQLite 后：原 `processed/` 中间层由 SQLite 取代（见 [10](10-数据存储与SQLite.md)），
> 但 **`raw/` 与「只处理、不爬取」原则不变**；另增「Web 交互式导入」路径 —— 上传 xlsx 先落
> `ImportBatch` 暂存，未匹配选手由人工逐个决策后才写正式表（见 [08-前端与Web交互模块](08-前端与Web交互模块.md) §4.4）。

---

## 1. 模块职责

- 定义 `data/raw` → SQLite 的**格式、目录与处理顺序**
- 实现「**只处理、不爬取**」：数据由人工/外部系统放入 `raw/`
- 提供 CLI：`xcpc-data import`（包结构统一后的入口），以及 Web 在线导入（三期）

---

## 2. 目录结构

```
data/
├── raw/                              # 人工投放的原始文件（可 diff、可进 Git）
│   ├── players/                      # 选手名册 roster.json
│   ├── teams/                        # 队伍名册 roster.json
│   ├── formal/                       # 正式赛单场文件 {contest_id}.json
│   ├── training/                     # 训练赛单场文件（设计中）
│   └── oj/
│       ├── contests/
│       └── snapshots/
├── db/xcpc.db                        # SQLite（WAL），gitignore
├── uploads/                          # Web 上传的 xlsx 暂存
└── public/                           # 可选只读导出 / 备份（见 [05](05-数据导出与发布模块.md)）
```

> `processed/` 目录**废弃**，其职责由 SQLite 承担。`schemas/` 不再维护（字段形状以 Pydantic DTO 为准）。

---

## 3. 处理阶段

```
┌─────────┐    import     ┌──────────────┐
│  raw/   │ ────────────▶ │  校验+匹配     │
└─────────┘               │  选手/队伍     │
                          └──────┬───────┘
                                 ▼
                          SQLite（Contest / Standing / Player / Team / OJ*）
                                 │
                                 ▼（派生）
                          rating_events（可重建，非事实来源）
```

| 阶段 | 输入 | 输出 |
|------|------|------|
| 解析+校验 | `raw/**` | 解析结果 + 未匹配项 |
| 落库 | 解析结果 | SQLite 各表 |

CLI 路径（迁移后）：`python -m xcpc_core.importer.cli import ...`；
Web 路径（三期）：上传 xlsx → 预览 → 人工匹配 → 确认落库。

## 4. 原始数据（raw）约定

### 4.1 原则

- 一文件一场次或一批快照，文件名建议带日期：`{contest_id}.json` 或 `{platform}_{date}.csv`
- **不修改 raw**：重跑 import 只读 raw，便于复现
- 支持格式：选手名册 **JSON**；OJ 等导出可为 CSV / JSON

### 4.2 选手名册 `raw/players/roster.json`

当前实现样例见 **`data/raw/players/roster.json`**（ID `p001` 起，全局递增）。

```json
[
  {
    "id": "p001",
    "name": "张三",
    "grade": 2023,
    "oj_accounts": [
      { "platform": "codeforces", "handle": "zhangsan_cf" }
    ]
  }
]
```

### 4.3 正式赛 `raw/formal/{contest_id}.json`

由 `importer.import_formal_xcpcio_xlsx` 从 XCPC.io 导出的 `.xlsx` 生成，字段含：
`contest_id` / `date` / `contest_type` / `format` / `total_teams` / `award_thresholds` /
`weight`（由 `data/config/contest_weights.yaml` 按 `contest_type` 查表，可 `weight_override`）/
`standings`（每队：`team_id`、`member_names`、`player_ids`、`rank`、`school_rank`、`award`、`solved`、`penalty`、`unofficial`）/
`unmatched_players` / `unmatched_teams`。

示例见 `data/raw/formal/2026_sichuan_provincial.json` 与 [03-比赛与记录模块](03-比赛与记录模块.md) §3.4。

### 4.4 导入约定

- 队员姓名解析：按姓名/别名匹配选手，歧义或未匹配进 `unmatched`，不盲目自动建号
- `auto_create_players=True` 时按 `data/config/school.yaml` 的 `player_defaults.grade` 自动建档
- 队伍：按队员集合 `member_key` 查找或创建，队名追加到 `aliases`（见 [03](03-比赛与记录模块.md)）
- 重复导入：同一 `contest_id` + 队伍以最新导入为准（`_upsert_standing`）

## 5. Web 交互式导入（三期）

**这是 Reflex 改造的核心价值**：导入 xlsx 不再需要写一段 `python -c` 脚本。

```
步骤 1  上传          [选择 .xlsx]  [上传]
步骤 2  填元信息      contest_id / 日期 / contest_type（→ 自动查权重）
步骤 3  解析预览      312 队，本校 8 队，奖牌线自动推算
步骤 4  匹配未识别    「李某某」→ [新建选手 ▼] [p003 李冉曦]
步骤 5  确认写入      [取消]  [确认导入]
```

关键设计：**解析结果先落 `ImportBatch`（`status=staged`），确认后才写正式表。**
中途关页面不会产生半截数据；未匹配项由人工逐个决策，替代
`auto_create_players=True` 盲目自动建号。

页面细节见 [08-前端与Web交互模块](08-前端与Web交互模块.md) §4.4，`ImportBatch` 表定义见 [10](10-数据存储与SQLite.md) §4.3。

## 6. 与「不爬取」的边界

| 做 | 不做 |
|----|------|
| 解析 raw 下人工放置的文件 | 请求 OJ 网站 API |
| 校验、合并、去重 | 定时爬比赛榜单 |
| 写入 SQLite | 运行时拉取外部数据 |

外部系统（办赛平台、OJ 导出脚本）负责把文件放进 `raw/` 或通过 CI / Web 上传。

## 7. 现有实现（迁移前）

当前 `xcpc_core/importer/` 已实现：

| 文件 | 职责 |
|------|------|
| `formal.py` | `import_formal_xcpcio_xlsx` / `add_formal_team` 主流程 |
| `xcpcio_xlsx.py` | XCPC.io xlsx 榜单解析 |
| `players.py` | 队员姓名解析与自动建档 |
| `awards.py` | 奖牌线推算与获奖分配 |
| `weights.py` / `config.py` | 权重表与 school.yaml 读取、赛年/赛季标签 |
| `formal_store.py` | raw 正式赛文件读写 |

迁移到 `xcpc_core/importer/` 时，**解析与校验逻辑不动**，仅输出端从写 JSON 改为写 SQLite。
