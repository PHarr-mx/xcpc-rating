# 开发环境与工程结构

> 关联：[DESIGN.md](DESIGN.md) · [12-开发流程建议](12-开发流程建议.md) · [13-实施路线图](13-实施路线图.md)

本文定义目标工程结构、包管理方式与**两条硬性分层规则**，并说明当前代码（`backend/data`）与目标结构（`xcpc_core`）的迁移对应关系。

---

## 1. 目标工程结构

用一个 `pyproject.toml` 统一打包，解决当前 PYTHONPATH hack 造成的包结构扁平化问题。

```
xcpc-rating/
├── pyproject.toml              # 唯一包管理入口，替代 PYTHONPATH hack
├── rxconfig.py                 # Reflex 配置
├── alembic/                    # reflex db init 生成
├── xcpc_core/                  # 纯业务层，不 import reflex
│   ├── db/                     # 表定义 + session + 迁移脚本
│   ├── player/  team/          # 由现有 backend/data/{player,team} 迁入
│   ├── contest/                # formal + training 统一
│   ├── importer/               # 由现有 backend/data/import 迁入（import 是关键字）
│   ├── rating/                 # 按 06 文档实现 BaseRatingCalculator 体系
│   ├── board/                  # 按 07 文档实现榜单聚合
│   └── auth/                   # 用户、角色、绑定选手
├── xcpc_web/                   # Reflex 应用，只做 UI 与状态
│   ├── xcpc_web.py             # app = rx.App(...)
│   ├── states/  pages/  components/  assets/
├── data/
│   ├── raw/                    # 保留：人工投放归档 + 导入源，可 diff 可进 Git
│   ├── db/xcpc.db              # SQLite，gitignore
│   ├── uploads/                # 上传的 xlsx 暂存
│   └── public/                 # 降级为可选：对外只读导出 / 备份快照
└── docs/
```

> `backend/`、`frontend/` 目录在迁移后废弃：`backend/data/*` 迁入 `xcpc_core/`，`frontend/` 不再创建（Reflex 编译产物取代手写 Vue）。

## 2. 两条硬性分层规则

**`xcpc_core` 绝不 `import reflex`。**

CLI、pytest、未来的定时任务都能脱离 web 运行，现有测试的价值全部保留。

**`xcpc_web` 绝不写 SQL，也不承载业务规则。**

State 只做四件事：读表单 → 调 `xcpc_core` 函数 → 转视图模型 → 写 state var。

违反任一条，都会让业务逻辑与框架绑死，后续换框架或加 CLI 入口都要重写。

### 2.1 DTO 与 ORM 分离

`xcpc_core` 内部，领域对象用 **Pydantic DTO**（现 `models.py` 的 `Player`/`Team` 等），数据库层另建 **`rx.Model` ORM 表**，两者**显式互转**。

- 理由：ORM 实例渗进 service 层会把 SQLAlchemy session 生命周期问题扩散各处（detached instance、懒加载越界），也污染干净的业务校验（如 `_validate_unique_constraints`）。
- 代价是多一层转换代码；收益是 service 层可单测、不需要 DB fixture。
- 详见 [10-数据存储与SQLite](10-数据存储与SQLite.md) §3。

## 3. 当前代码与目标的迁移对应

| 当前（`backend/data`） | 目标（`xcpc_core`） | 说明 |
|------------------------|---------------------|------|
| `player/{models,store,service,api,cli}` | `xcpc_core/player/` | store 层由 JSON 全量读写重写为 repository |
| `team/{models,store,service,api,cli}` | `xcpc_core/team/` | 同上 |
| `import/`（formal、xcpcio_xlsx、players、awards、weights…） | `xcpc_core/importer/` | 导入逻辑不变，输出从 JSON 改为写 SQLite |
| `utils/plog.py` | `xcpc_core/...` 或独立 util 包 | 双写日志保留 |
| （无） | `xcpc_core/contest/`、`rating/`、`board/`、`auth/` | 新模块，按 03/06/07/09 文档实现 |

**API 层签名保持不变**：`api.py → service.py → store.py → JSON` 的分层正好把持久化隔离了，迁移只改 store 层，CLI 与现有测试不用改。

## 4. 开发环境

```bash
source ./setup_env.sh   # 创建 conda 环境 xcpc_rating、安装依赖、设置 PYTHONPATH
```

当前 `setup_env.sh` 设置 `PYTHONPATH="${ROOT}/backend/data:${ROOT}/backend"`，使 `player`/`team`/`importer`/`utils` 成为顶层包。**这是过渡状态**：一期地基（[13](13-实施路线图.md)）完成 `pyproject.toml` 后，包由安装机制解析，不再依赖 PYTHONPATH。

测试：

```bash
cd backend && python -m pytest data/tests/ data/import/tests/ utils/tests/ -v
# 单个测试
cd backend && python -m pytest data/tests/test_team_crud.py -v
```

> 测试须在 `backend/` 下运行且 PYTHONPATH 已生效；迁移到 `xcpc_core` 后改在项目根目录运行。
