## 1. 部署形态

- Caddy 直接托管前端静态产物，只反代后端（省资源）
- `reflex run --env prod` 默认前端 3000、后端 8000
- 数据文件与备份自掌控

## 2. 构建

```bash
# 需要 Node/bun。本地构建后 rsync 产物，服务器保持干净
reflex export --frontend-only --no-zip     # → .web/build/client/
rsync -a .web/build/client/ server:/var/www/xcpc-rating/
```

## 3. `rxconfig.py` 生产化

```python
config = rx.Config(
    app_name="xcpc_web",
    api_url="https://rating.example.com",   # 公网可达地址
    db_url="sqlite:///data/db/xcpc.db",
)
```

> `api_url` 配错是自托管最常见的坑——它决定浏览器往哪连 WebSocket；写 `localhost` 只有本机能用。可用环境变量 `API_URL` 覆盖。当前 `rxconfig.py` 仅本地开发配置（⬜ 生产化待做）。

## 4. Caddyfile（设计）

```caddyfile
rating.example.com {
    encode gzip zstd

    # 后端：事件 WebSocket、上传、健康检查。Caddy 自动处理 WS 升级
    @backend path /_event* /_upload* /_health* /ping* /_all_routes*
    reverse_proxy @backend localhost:8000

    root * /var/www/xcpc-rating
    @assets path /assets/*
    header @assets Cache-Control "public, max-age=31536000, immutable"
    try_files {path} {path}/ /index.html
    file_server
}
```

后端挂子路径用 Reflex 的 `backend_path`，代理侧无需重写。

## 5. systemd 与备份（设计）

```ini
# /etc/systemd/system/xcpc-rating.service
[Service]
WorkingDirectory=/opt/xcpc-rating
ExecStart=/opt/xcpc-rating/.venv/bin/reflex run --env prod --backend-only
Restart=always
Environment=API_URL=https://rating.example.com
[Install]
WantedBy=multi-user.target
```

```cron
30 4 * * * sqlite3 /opt/xcpc-rating/data/db/xcpc.db ".backup '/var/backups/xcpc-$(date +\%F).db'"
```

用 `.backup` 而非 `cp`（对正在写入的库安全）；`data/raw/` 已在 Git，本身是可追溯冷备。

## 6. 风险与约束

| 风险 | 说明 | 应对 |
|------|------|------|
| **预渲染泄露** | 组件树里的数据对所有人可见 | 私有数据必经带权限的 computed var（[05](05-Web与认证.md) §7.3） |
| **内存状态与单进程** | State 在进程内存（按 client token 索引），多 worker 同一用户落到不同进程 | **不要加 `--workers`**；顺带保证 SQLite 单写进程（[01](01-架构与数据流.md) §5.3） |
| **SQLite 写并发** | 多人同时写可能锁表 | WAL 三件套（[01](01-架构与数据流.md) §5.1）；真不够换 Postgres，core 一行不改 |
| **构建期工具链** | 服务器需 Node/bun | 本地构建 rsync 产物（§2） |
| **Reflex 版本流动** | 0.9.x 变化快 | 版本锁死，升级独立任务 |
| **公网垃圾注册** | 自由注册无限制 | 上线前决策注册限制（邀请码/域名白名单，[08-路线图](08-路线图.md) §4） |
