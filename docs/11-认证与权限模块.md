# 认证与权限模块

> **状态：提案 · 待评审 · 未实施**
> 隶属于 [09-Reflex-Web改造提案](./09-Reflex-Web改造提案.md)
> 关联：[10-数据存储与迁移](./10-数据存储与迁移-SQLite.md) · [12-Web交互与页面](./12-Web交互与页面-Reflex.md)

本文定义多用户自助场景下的角色、用户↔选手绑定流程，以及权限校验的落点。

---

## 1. 选型

用 **`reflex-local-auth`**：基于自己的数据库，不引外部身份提供商，与校内自用场景匹配。

Reflex 官方文档只汇总社区方案并给安全建议，**框架没有内置认证，也没有内置的
protected route 机制**。这意味着「路由保护」必须自己在事件处理器和 loader 里实现，
见 §4。

### 1.1 库提供什么 / 我们写什么

| 由 `reflex-local-auth` 提供 | 我们自己写 |
|---|---|
| `LocalUser` 表：用户名、密码哈希、`enabled` 标志 | `UserProfile` 表：角色、绑定的选手（§5） |
| `LocalAuthSession` 表：会话 | `BindingRequest` 表：绑定申请与审批（§5） |
| `LocalAuthState`：`is_authenticated`、`authenticated_user`、`do_logout` | `AuthState`：在其上加 `is_admin`、`bound_player_id` |
| `LoginState` / `RegistrationState`：登录注册流程 | 注册后补写 `UserProfile`（扩展 `RegistrationState`） |
| `@require_login` 装饰器：**仅重定向** | 真正的权限校验（§4） |

**密码哈希与验证由 `LocalUser` 内部完成**，我们不自己存 `password_hash`、不自己选哈希算法。

---

## 2. 角色

三个角色，外加一条「用户 ↔ 选手」绑定关系：

| 角色 | 能做 |
|------|------|
| `guest`（未登录） | 看榜单、选手详情、比赛详情 |
| `member`（已绑定选手） | 上述 + 改**自己**的 OJ 账号、别名、校内 handle |
| `admin` | 全部 CRUD、导入比赛、改 grade/status、审批绑定、看审计日志、权重试算 |

`member` 的写权限严格限定在自己绑定的 `player_id` 上。判断依据是**服务端从 session
查出的 `bound_player_id`**，不接受客户端传入的任何 ID。

---

## 3. 字段级权限

| 字段 | member 改自己 | admin | 理由 |
|------|:---:|:---:|------|
| `oj_accounts` | ✅ | ✅ | 本人最清楚自己的账号；这是自助的主要价值 |
| `aliases` | ✅ | ✅ | 曾用名/英文名 |
| `handle`（校内简称） | ✅ | ✅ | 唯一性由 DB 约束兜底 |
| `name` | ❌ | ✅ | 影响导入时的选手匹配 |
| `grade` | ❌ | ✅ | 影响榜单分组 |
| `status` | ❌ | ✅ | `left` 决定是否从榜单隐藏，不能自己改 |
| 比赛成绩 | ❌ | ✅ | 事实数据，只能由导入写入 |

`name` / `grade` / `status` 是 admin-only 的原因值得记下来：它们影响 Rating 归属与榜单
可见性。让本人自行修改，等于让被统计者改统计口径。

## 4. 权限校验的三个落点

**Reflex 会把页面静态预渲染。** 写在组件树里的常量会进 HTML，对所有人可见。
用 `rx.cond` 隐藏 admin 按钮只是体验优化，**不是安全边界**。

### 4.0 先分清「重定向」与「防护」

这是本模块最容易搞错的地方，单独说明：

| 手段 | 作用 | 是防护吗 |
|------|------|:---:|
| `@require_login` 装饰器 | 未登录时跳转到登录页 | ❌ |
| `on_load` 守卫 | 无权限时跳转走 | ❌ |
| `rx.cond` 隐藏组件 | 不显示按钮 | ❌ |
| **事件处理器内校验** | 拒绝执行写操作 | ✅ |
| **computed var 内校验** | 私有数据不出库 | ✅ |

`reflex-local-auth` 的文档对 `@require_login` 说得很直接：它「是把用户重定向到登录页的
机制，**不是保护数据的方式**」—— 因为被装饰页面的静态内容看网页源码就能拿到。

**结论：真正的防护只有两处 —— §4.1 事件处理器、§4.2 computed var。**
§4.3 的 `on_load` 是体验层，不能替代前两者。三处都要写，但要清楚各自的作用。

### 4.1 事件处理器 —— 每个写操作

```python
class AuthState(reflex_local_auth.LocalAuthState):
    """全局认证状态。在库的 LocalAuthState 上叠加本项目的角色与绑定。"""

    @rx.var
    def profile(self) -> UserProfileView | None:
        if not self.is_authenticated:
            return None
        return auth_api.get_profile(self.authenticated_user.id)

    @rx.var
    def is_admin(self) -> bool:
        return self.profile is not None and self.profile.role == "admin"

    @rx.var
    def bound_player_id(self) -> str | None:
        return self.profile.bound_player_id if self.profile else None


class ProfileState(AuthState):
    @rx.event
    def add_oj_account(self, form: dict):
        if not self.is_authenticated:
            return reflex_local_auth.LoginState.redir
        pid = self.bound_player_id          # 服务端从会话推出，不接受客户端传入的 ID
        if pid is None:
            return rx.toast.error("账号未绑定选手")
        try:
            player_api.add_oj_account(pid, form["platform"], form["handle"])
        except PlayerValidationError as exc:
            return rx.toast.error(str(exc))
        audit(self.authenticated_user.id, "player.oj.add", pid, form)
```

`bound_player_id` 是 computed var，每次读都从会话推导，**不缓存在可写 state var 里** ——
否则客户端有机会通过某个 setter 覆盖它，就能改别人的选手。

### 4.2 computed var —— 私有数据的出口

```python
    @rx.var
    def pending_bindings(self) -> list[BindingView]:
        if not self.is_admin:
            return []
        return auth_api.list_pending_bindings()
```

官方安全建议明确要求：**所有访问私有数据的 computed var 与 loader event 都要校验**。
这一处最容易漏 —— 页面已经用 `rx.cond` 藏了组件，容易误以为数据不会外传。

### 4.3 `on_load` + `@require_login` —— 体验层，非防护

```python
@rx.page(route="/admin/players", on_load=AdminPlayerState.on_load)
@reflex_local_auth.require_login
def admin_players() -> rx.Component: ...
```

```python
class AdminPlayerState(AuthState):
    players: list[PlayerView] = []

    @rx.event
    def on_load(self):
        if not self.is_admin:
            return rx.redirect("/")
        self.players = player_api.list_players()   # 校验通过后才取数据
```

装饰器顺序：`@rx.page` 在外、`@require_login` 在内。

两点必须记住：

- `@require_login` 只处理「未登录」，**不认识 admin 角色** —— 角色判断得自己在
  `on_load` 与事件处理器里写。
- 这两者都只是把人赶走，**页面里已渲染的静态内容仍然公开**。
  所以数据要在 `on_load`（校验后）或 §4.2 的 computed var 里取，
  绝不能作为静态内容写进组件树。

### 4.4 敏感数据不进 state var

官方建议把敏感令牌放 **backend-only var**（不同步到浏览器的状态）。
密码哈希、session token 一律不进普通 state var。

## 5. 表结构

**不自定义用户表。** `LocalUser`（凭据）与 `LocalAuthSession`（会话）由
`reflex-local-auth` 建，我们只加一张 profile 表用外键扩展：

```python
class UserProfile(rx.Model, table=True):
    """扩展 LocalUser。凭据与会话由 reflex-local-auth 管理，此表不含任何密码字段。"""
    user_id: int = Field(foreign_key="localuser.id", unique=True, index=True)
    role: str = "member"                       # member|admin
    bound_player_id: str | None = Field(
        default=None, foreign_key="player.id", unique=True
    )                                          # unique: 一个选手最多绑一个用户
    created_at: datetime
    last_login_at: datetime | None = None

class BindingRequest(rx.Model, table=True):
    """绑定申请，需 admin 审批。"""
    user_id: int = Field(foreign_key="localuser.id", index=True)
    player_id: str = Field(foreign_key="player.id", index=True)
    reason: str | None = None                  # 申请说明，便于 admin 判断
    status: str = "pending"                    # pending|approved|rejected
    reviewed_by: int | None = None
    created_at: datetime
    reviewed_at: datetime | None = None
```

> `localuser` / `localauthsession` 是库的表名（0.1.x 起由 `user` / `authsession` 改名）。
> 外键写错表名，迁移时才会报错，值得在一期就确认实际表名。

注册时扩展 `RegistrationState`：调 `self.handle_registration(form_data)`，成功后用
`new_user_id` 在**同一事务**内插入 `UserProfile`。否则会出现有凭据但无 profile 的用户。

审计表 `AuditLog` 见 [10](./10-数据存储与迁移-SQLite.md) §4.3。

## 6. 绑定流程

```
注册 → 登录（role=member, bound_player_id=null）
     → 从选手名册里选一个 player_id，提交 BindingRequest（可填说明）
     → admin 在 /admin/users 审批
     → approved: User.bound_player_id = player_id
     → 此后该用户可编辑该选手的自助字段
```

**不允许自助绑定。** 否则任何注册用户都能认领别人的成绩。

约束：

- 一个 `player_id` 最多绑一个 `User`（DB 唯一约束）
- 一个 `User` 最多绑一个 `player_id`
- 已绑定后要换绑，需 admin 先解绑
- 首个 admin 由 CLI 创建：`python -m xcpc_core.auth.cli create-admin`

## 7. 审计

所有写操作落 `AuditLog`：`user_id` / `action` / `target` / `diff_json` / `at`。

| action 示例 | 触发 |
|-------------|------|
| `player.create` `player.update` `player.delete` | 选手 CRUD |
| `player.oj.add` `player.oj.remove` | OJ 账号变更（含自助） |
| `team.create` `team.alias.add` | 队伍操作 |
| `contest.import` `contest.delete` | 比赛导入/删除 |
| `binding.approve` `binding.reject` | 绑定审批 |
| `weights.apply` | 权重变更 |
| `user.role.change` | 角色调整 |

`diff_json` 只存变化的字段，不存全量快照。

## 8. 开放问题

| 项 | 状态 | 说明 |
|----|------|------|
| 是否开放自由注册 | 待定 | 建议加邀请码或域名限制，否则公网会有垃圾注册 |
| 密码找回 | 待定 | 无邮件服务，建议由 admin 重置 |
| `retired` 选手的绑定用户是否保留写权限 | 建议保留 | 退役不等于离队，数据仍属本人 |
| `left` 选手的绑定 | 建议自动解绑 | 与榜单隐藏策略一致 |
