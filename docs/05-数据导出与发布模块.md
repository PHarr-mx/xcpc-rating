# 数据导出与发布模块设计（可选）

> 关联：[DESIGN.md](DESIGN.md) · [数据导入与加工](./04-数据导入与加工模块.md) · [Rating计算](./06-Rating计算模块.md) · [榜单](./07-榜单模块.md) · [数据存储与SQLite](./10-数据存储与SQLite.md)

> **已采纳 Reflex + SQLite 后，本模块降级为「可选」**：
> `data/public/` 不再是前端数据源（Reflex 运行时直接算），仅保留两个用途：
> **对外只读 JSON 导出** 与 **定期快照备份**。§5 的榜单文件矩阵与 `index.json` 均不再需要。
> §6 的原子导出逻辑保留给备份用。

---

## 1. 模块职责

- 将 SQLite 中的规范化数据**导出为** `data/public/` 只读 JSON（可选）
- 提供 CLI：`xcpc-data export`
- 保证导出**原子性**：失败不破坏上一轮 `public/`

Rating 数值计算**不在本模块**——由运行时 `xcpc_core/rating` 按需计算（见 [06](06-Rating计算模块.md)），
本模块只负责把当前 DB 状态快照成 JSON。

---

## 2. 目录结构（public）

```
data/
└── public/                           # 可选只读导出 / 备份快照
    ├── meta.json                     # data_version、算法版本、统计
    ├── players/                      # {id}.json
    ├── contests/                     # {contest_id}.json
    └── ratings/                      # 可选：各模式×周期的榜单快照
```

> `raw/` 与 `db/` 由 [数据导入与加工](./04-数据导入与加工模块.md) 与 [数据存储与SQLite](./10-数据存储与SQLite.md) 负责。

---

## 3. 处理阶段

```
SQLite 各表
    │
    ├── 可选：rating 计算（运行时，按需）
    ▼
public/**（原子导出：先写 .staging，再整体替换）
```

| 阶段 | 输入 | 输出 |
|------|------|------|
| export | SQLite 全部 + 可选 rating 快照 | `public/**` |

---

## 4. 原子导出

```python
# 伪代码
def export_public(out_dir: Path):
    staging = out_dir / ".staging"
    write_all(staging)          # 从 SQLite 读取当前状态
    validate_schemas(staging)   # 可选
    atomic_replace(staging, out_dir)
```

失败时保留上一轮 `public/`，并写 `meta.json` 的 `last_error`（可选）。

## 6. 对外只读 JSON

如存在外部消费者（第三方站点、只读展示），提供 `players/{id}.json` 与 `contests/{id}.json`
的结构化导出。**若无消费者，本模块整体可砍掉**（见 §8 开放问题）。

---

## 7. 与备份的关系

SQLite 的每日备份用 `sqlite3 .backup` 完成（见 [11-部署与运维](11-部署与运维.md) §5），
与 `public/` 导出是两回事：前者是 DB 快照，后者是面向消费方的 JSON 视图。

---

## 8. 开放问题

| 项 | 状态 |
|----|------|
| `public/` 只读导出是否真有外部消费者 | 待确认，无则可完全砍掉 |
| 是否保留 `xcpc-data dump-json` 便于脱库审阅 | 建议保留，输出到 `data/public/` |
| 榜单快照是否随导出生成 | 默认不生成，运行时按需算 |
