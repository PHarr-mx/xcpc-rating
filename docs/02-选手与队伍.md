# 选手与队伍

> 定位：**参考**（描述已实现的系统）。关联：[01-架构与数据流](01-架构与数据流.md) · [03-比赛与导入](03-比赛与导入.md)

Player 与 Team 是 Rating 的统计主体。两个模块采用完全一致的「六件套」分层（见 [01](01-架构与数据流.md) §2.1），
**对外唯一读写入口是 `xcpc_core.player.api` / `xcpc_core.team.api`**（CLI 与其他子模块同样从这里走），
禁止绕过 API 直接读写 SQLite 或 raw JSON。

---

## 1. 选手（Player）

### 1.1 字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | str | 校内 ID，`p001` 起全局递增（`PlayerStore.next_id()`），可显式指定 |
| `name` | str | 真实姓名，**admin-only**（影响导入时的选手匹配） |
| `handle` | str \| None | 校内简称，UNIQUE；自助字段 |
| `grade` | int | 入学年；**`0` 表示未设置**（榜单显示「未设置」） |
| `status` | enum | 状态机，见 §1.2 |
| `oj_accounts` | list[OJAccount] | `platform`（codeforces/atcoder/luogu/nowcoder）+ `handle`，**UNIQUE(platform, handle)** |
| `aliases` | list[str] | 曾用名/英文名，UNIQUE(player_id, alias)，导入匹配也用它 |
| `created_at` / `updated_at` | date | |

### 1.2 状态机

| 状态 | 语义 | 榜单行为 |
|------|------|----------|
| `probation` | 预备队员（入队考核中） | 打过比赛即可上榜 |
| `active` | 现役 | 正常上榜 |
| `retired` | 退役 | **保留**档案、历史成绩与 Rating，上榜并带退役标记 |
| `left` | 离队（软删除） | **不出现在榜单**，数据保留 |

流转规则：

- `probation → active`：入队（`mark_active`，仅 probation 可调用，防止退役/离队选手被「入队」复活）
- `active → retired`（`mark_retired`）、`active → left`（`mark_left`）
- 其他状态变更走 `update_player` 显式修改（admin 权限）
- `left` 是软删除；`delete_player` 为**物理删除**（连带 oj_accounts / aliases）

### 1.3 字段级权限

| 字段 | 绑定 member 改自己 | admin |
|------|:---:|:---:|
| `oj_accounts` / `aliases` / `handle` | ✅ | ✅ |
| `name` / `grade` / `status` | ❌ | ✅ |

admin-only 的原因：`name` 影响导入匹配、`grade` 影响榜单分组、`status` 决定榜单可见性——
让本人修改等于让被统计者改统计口径。自助编辑入口在 `/profile`（见 [05-Web与认证](05-Web与认证.md)）。

### 1.4 唯一性与校验

唯一性由 DB 约束兜底（`handle` UNIQUE、`(platform, handle)` UNIQUE、`(player_id, alias)` UNIQUE），
service 层捕获 `IntegrityError` 转成 `PlayerValidationError`，消息可直接展示到 UI（如「OJ 账号已绑定其他选手」）。

## 2. 队伍（Team）

### 2.1 身份规则：队员集合决定队伍

- **队伍身份由队员集合决定，与队名无关**：`make_member_key` = 排序后 `"p001|p002|p003"`，UNIQUE+INDEX
- 同名队员不同队名 → **同一支队伍**（新队名追加进 `aliases` 队名历史）
- 换员（任一队员变动）→ `member_key` 变化 → **新队伍**
- 1–3 人；成员写入 `teammember`（含 `seat`）

### 2.2 Web 编辑约束

Web 端编辑队伍遵循 `skill/team-manage/SKILL.md`：**只追加别名，不原地修改 members**；换员请新建队伍。
创建/更新/删除均写 `team.create|update|delete` 审计。

## 3. API 与 CLI 速查

### 3.1 选手 API（`xcpc_core.player.api`）

| 函数 | 说明 |
|------|------|
| `list_players(include_left, status, grade, store)` | 列表 + 筛选 |
| `get_player(player_id, store)` | 单查，不存在抛 `PlayerNotFoundError` |
| `find_by_name(name, grade, store)` | 按姓名或别名（导入匹配用） |
| `find_by_oj(platform, handle, store)` | 按 OJ 账号查 |
| `create_player(data, today, store)` | 新建（含唯一性校验、ID 生成） |
| `update_player(player_id, data, today, store)` | 更新（仅提交的字段生效） |
| `delete_player(player_id, today, store)` | 物理删除 |
| `mark_left / mark_retired / mark_active(player_id)` | 状态流转 |

session 生命周期：facade 未注入 `store` 时自建短事务 session 并在 finally 关闭（**注入 store 则由调用方管理**）——
这是修复「连接池耗尽」后的约定，测试与 Web 注入 store 时不得泄漏。

### 3.2 队伍 API（`xcpc_core.team.api`）

`create_team(TeamCreate(members=...))` / `update_team` / `delete_team` / `list_teams` /
`find_by_member_key` / `find_by_members` / `add_alias`。冲突预检：按队员集合建重队时提示已存在的队。

### 3.3 CLI

```bash
python -m xcpc_core.player.cli list --visible-only
python -m xcpc_core.player.cli get p001 --json
python -m xcpc_core.player.cli create|update|delete|mark-left|mark-retired|mark-active ...
python -m xcpc_core.team.cli list
python -m xcpc_core.team.cli find --members p001 p002
python -m xcpc_core.team.cli create --members p001 p002 --aliases 队名
```

（安装后亦可用 console_scripts：`xcpc-player` / `xcpc-team`。）

## 4. 与导入的联动

- 正式赛导入解析队员姓名时按 `name`/`aliases` 匹配；歧义或未匹配进 `unmatched`，不盲目建号
- staged 流程中管理员对未匹配选手逐个决议「新建 / 指定已有」，新建走 `create_player(commit=False)` 并入确认大事务
- 队伍按 `member_key` 查找或创建，队名追加进 `aliases`
- 详见 [03-比赛与导入](03-比赛与导入.md)

## 5. 审计动作

`player.create` / `player.update` / `player.delete` / `player.oj.add` / `player.oj.remove` /
`team.create` / `team.update` / `team.delete`；绑定审批为 `binding.approve` / `binding.reject`（见 [05-Web与认证](05-Web与认证.md) §7）。
