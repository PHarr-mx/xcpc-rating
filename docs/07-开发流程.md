## 1. 开发环境

```bash
source ./setup_env.sh   # uv sync + 激活 .venv（Python 3.13 由 .python-version 锁定）
```

测试（**两套分开跑**，根 `pyproject.toml` 的 `testpaths` 只含 core）：

```bash
uv run python -m pytest xcpc_core -v                    # core（在项目根目录）
cd xcpc_web && ../.venv/bin/python -m pytest tests -v   # web State 层测试
```

Web 应用：`cd xcpc_web && ../.venv/bin/reflex run`（端口 3000）。

## 2. 工程分层与编码约定

### 2.1 两条硬性规则（违反就重写）

- **`xcpc_core` 绝不 `import reflex`**——业务层必须能脱离 web 运行（CLI / pytest）
- **`xcpc_web` 绝不写 SQL、不承载业务规则**——State 只做「读表单 → 调 core → 转视图模型 → 写 var」

### 2.2 CRUD 六件套（新增域对象照抄 player/team 模式）

| 文件 | 职责 | 关键点 |
|------|------|--------|
| `models.py` | Pydantic DTO | Base/Create/Update/实体 + 校验器 |
| `store.py` | SQLAlchemy repository | DTO↔ORM 转换在 store 边界 |
| `service.py` | 业务逻辑 | 唯一约束、ID 生成、筛选；**写路径 bump data_version**（`db/meta.bump_data_version`，只 flush 随调用方事务提交） |
| `api.py` | **对外唯一读写入口** | CLI 与子模块都从这里导入；注入 store 时 session 由调用方管理 |
| `cli.py` | argparse 命令行 | |
| `exceptions.py` | 模块异常 + 子类 | 消息可直接展示到 UI |

### 2.3 其他约定

- **DTO 与 ORM 分离**（见 [01](01-架构与数据流.md) §2.2）；**唯一性下沉 DB**：service 捕 `IntegrityError` 转领域异常
- **`find_repo_root()`** 基于 `data/raw` 标志目录向上定位仓库根；测试注入临时路径
- 队伍身份由 `member_key`（排序后队员集合）决定，与队名无关
- 每个写操作写审计（`xcpc_core.audit.api`，best-effort）
- 列表类 computed var **`cache=False`**（见 §5 坑）

## 3. 推荐开发循环

```
1. 先在 xcpc_core 用 pytest 把逻辑跑通     ← 不依赖 Reflex，快且可测
2. CLI 冒烟（如 python -m xcpc_core.player.cli list）
3. 再包 Reflex State：只做视图与交互        ← 逻辑已在 core，State 薄
4. 页面组件；私有数据走带权限的 computed var
```

每个 Part 独立可验收：跑起一个命令、看到一个能用的页面即算完成；合入前两套测试全绿。

## 4. 常用任务速查

| 任务 | 做法 |
|------|------|
| 导入正式赛 xlsx | Web `/admin/import`（五步）；CLI 走 `importer.import_formal_xcpcio_xlsx`（skill：formal-import） |
| 补录打星队 | `importer.add_formal_team`（award 须达奖线） |
| 选手 / 队伍 CRUD | `xcpc-player` / `xcpc-team` CLI 或 `player.api` / `team.api`（见 [02](02-选手与队伍.md) §3） |
| 改比赛权重 | `data/config/contest_weights.yaml`（formal 按 contest_type；training 按 division——加载器待建） |
| 建 / 重置 admin | `cd xcpc_web && ../.venv/bin/python create_admin.py --username u --password p [--reset-password]` |
| 跑一次性迁移 | `uv run python -m xcpc_core.db.migrate`（幂等，可重跑） |
| 备份 DB | `sqlite3 data/db/xcpc.db ".backup <路径>"` |
| 看数据版本 | 榜单页脚 `Data Version`；写路径自动 bump（[04](04-Rating与榜单.md) §7） |

## 5. 避坑清单

| 坑 | 后果 | 应对 |
|----|------|------|
| Reflex 版本不锁 | API 变化破坏代码 | 版本锁死 0.9.7，升级独立任务 |
| computed var `cache=True` 无 interval | **永不失效**——列表/自助字段同会话二次操作读到旧快照（连加 OJ 账号会覆盖前一个） | 列表类一律 `cache=False` |
| 预渲染泄露 | 组件树里的数据对所有人可见 | 私有数据走带权限的 computed var |
| 注册事务拆开 | 「有凭据无 profile」用户 | 覆写 `_register_user` 同事务补写 UserProfile |
| 测试导入 app 模块 | `rx.App()` 顶层副作用破坏手工状态链（跨测试 DB 复用、UNIQUE 冲突） | **测试中禁止 import `xcpc_web.xcpc_web`**（见 [05](05-Web与认证.md) §8） |
| 测试直读 `self.router` | router 是 Base 层继承 var，直接实例化的 State 赋值转发给不存在的 parent | 照运行时 processor：赋 `router_data` 后 `object.__setattr__`/按父链注入 RouterData |
| SQLite 只开 WAL | 仍有 `database is locked` | WAL + busy_timeout + 短事务三件套（[01](01-架构与数据流.md) §5.1） |
| PRAGMA 只设一次 | 外键/timeout 不生效 | 挂 `connect` 事件逐连接执行 |
| facade session 不关 | 连接池耗尽（Web 点不动） | 未注入 store 时 finally 关闭；注入时调用方负责 |
| 长任务放写事务 | 锁表 | 解析/重算与落库分短事务；`@rx.event(background=True)` |
| Pydantic 塞进 state var | 序列化不稳 | `rx.Base` 视图模型中转 |
| 绕过 api 改存储 | 约束失效、缓存不失效、审计缺失 | 一律走各模块 api；写路径 bump 已在 service 层自动生效 |
| 单进程约束被忽略 | 同一用户请求落到不同进程 | 不要加 `--workers` |
| `api_url=localhost` | 公网只有本机能连 | 部署时配公网地址 |

## 6. 分期要点（历史教训速览）

- **一期（地基 ✅ 2026-08-18）**：先统一包结构再动别的；开发期 `create_all`，schema 稳定再引 alembic；migrate 幂等。
- **二期（认证 ✅ 2026-08-20）**：三处校验点都写但只有「事件处理器 + computed var」是真防护；`@require_login` 不认识 admin 角色。
- **三期（管理后台 ✅ 2026-09-10）**：在线导入核心是 ImportBatch staged → 人工决议 → 单事务确认；浏览器手工验收是关闭里程碑的最后一关。
- **四期（业务补齐 ⬜）**：第一步是公式与分摊规则**业务定案**（不是写代码）；权重试算不落库不进缓存。
- **五期（上线 ⬜）**：本地构建 rsync；`api_url` 配公网；上线前决策注册限制。

两条顺序约束：一期最先；二期先于三期（否则先做出无认证的写接口）。

## 7. 与 AI Agent 协作

`skill/` 下提供 Agent 工作流（详见 `docs/README.md` §4 与各 `SKILL.md`）：

| 技能 | 触发场景 | 要点 |
|------|----------|------|
| `formal-import` | 正式赛导入 | 收集参数 → 预览解析 → 执行 → 补录打星队 → 报告 unmatched |

配合仓库根 **CLAUDE.md** 使用（命令、分层模式、文档索引）。给 Agent 的提示词建议包含：目标文件与模块路径（避免靠猜）、「只读/可写」边界、测试命令、遵循的文档与当前进度（08 路线图）。

技能文件约定：每技能一个子目录一个 `SKILL.md`；禁止爬取逻辑、子串匹配等不规范操作；CLI/API 路径随包结构同步更新。
