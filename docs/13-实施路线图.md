## 2. 两条顺序约束

- **一期必须最先**。包结构不统一，后面每步都在跟 PYTHONPATH 打架。
- **二期必须在三期之前**。否则会先做出一批无认证的写接口。

## 3. 各期详细内容

### 一期 · 地基 ✅（2026-08-18 完成）

- ✅ `pyproject.toml` 统一打包（uv + `.python-version`=3.13.14），`backend/data/*` 迁入 `xcpc_core/`
- ✅ SQLite 建表（`xcpc_core/db/tables.py`，纯 SQLAlchemy）+ store 重构为 repository + `migrate` 灌数据（24 选手/8 队伍/1 比赛，幂等）
- ✅ board 榜单聚合（`xcpc_core/board/`，[07](07-榜单模块.md)）：`BoardSnapshot`（meta+rows）、竞赛排名、`delta_recent`、`data_version` 进程内缓存（[06](06-Rating计算模块.md) §3）
- ✅ Reflex 骨架（`xcpc_web/`，P0 完成，首页展示真实数据版本）
- ✅ `/` 榜单只读页（P1 完成，BoardState 状态管理、筛选/排序/搜索、表格渲染）
- **开发要点与坑**见 [12](12-开发流程建议.md) §5

### 二期 · 认证 ✅（2026-08-20 完成）

- ✅ 接入 `reflex-local-auth`（0.5.0），`UserProfile` / `BindingRequest` 表 = web 层 SQLModel 存 `xcpc_web.db`（[09](09-认证与权限模块.md) §5，跨库 player FK 移除改 service 层校验）
- ✅ `AuthState`（登录/角色/绑定 computed var）+ `create_admin.py` CLI 一键建首个 admin
- ✅ `/login` `/register` / `/profile` 三页（注册同事务写 `LocalUser`+`UserProfile`；/profile 绑定申请 + 自助改资料 + OJ 账号管理）
- ✅ admin 权限三落点（[09](09-认证与权限模块.md) §4）：路由 on_load 重定向 / 事件处理器 `_require_admin` / computed var 空返回，落地在 `states/admin/`（`AdminState` 基类）
- ✅ `/admin` 概览 + `/admin/users` 绑定审批：批准/驳回、unique 预检（选手已被他人绑定 / 申请者已绑他人）、自动驳回其余 pending 申请
- ✅ 审计日志：`xcpc_core/audit/api.py`（AuditLog 写入，DI 模式镜像 `player_api`），审批写 `binding.approve`/`binding.reject`
- ✅ 测试基建：`xcpc_web/tests/`（conftest 状态链构造 + 39 条回归）
- **完成标志**：admin 校验三落点 + 完整绑定审批链路（申请→审批→绑定生效）✅
- **开发要点与坑**：reflex 0.9.7 computed var `cache=True` 无 interval = 永不失效（列表/自助字段 var 须 `cache=False`）；`super()` 事件异步入队坑（改覆写 `_register_user`）见 [12](12-开发流程建议.md) §5

### 三期 · 管理后台 ✅（2026-09-10 完成）

拆为 P4a–P4d 四个子 Part，详见 [14](./14-Web开发拆分计划.md)。

| Part | 内容 | 工作量 | 验收 |
|------|------|-------|------|
| **P4a** ✅ | `/admin/players` 选手 CRUD（列表/弹窗表单/软删） | 1d | 全程不敲 CLI 完成选手增删改 |
| **P4b** ✅ | `/admin/teams` 队伍 CRUD（队员集合建队/别名/member_key 冲突） | 0.5d | 全程不敲 CLI 完成队伍建改删 |
| **P4c** ✅ | `/admin/contests` 比赛管理 + `/admin/audit` 审计页 | 0.5d | 列表按 source 切、删除级联、审计按 user/action 筛 |
| **P4d** ✅ | `/admin/import` 在线导入五步 | 1d | 上传→元信息→预览→未匹配决策→确认写入走通 |

**顺序**：P4a→P4b→P4c，P4d 可并行（共享 admin 表单模式）。

**不变约束**：
- 全部走 `player.api` / `team.api` / `contest.api` / `xcpc_core.importer`（[12](./12-开发流程建议.md) §3.1）
- 写操作首行 `_require_admin()`（第 2 层守卫，`AdminState` 提供）
- 列表 computed var `cache=False`（二期坑）
- 审计 `audit_api.record(...)` 随每个写操作写入
- 唯一性冲突消息从 core 异常直接展示（[08](./08-前端与Web交互模块.md) §6）
- 每 Part 补测试（复用 `build_state`/`make_user`/`core_store` 管线）
- 导入解析先落 `ImportBatch(status=staged)` 再确认（[04](./04-数据导入与加工模块.md) §5）

**完成标志**：admin 全程不敲 CLI 完成选手/队伍增删改查与绑定审批；在线导入真实 xlsx 走通五步流程。

*注：P4a–P4d 的 Web 集成、自动化测试和真实 xlsx staged→confirmed 验证已于 2026-08-25 完成；浏览器手工验收于 2026-09-10 由管理员完成，全程未发现问题，三期关闭。*
