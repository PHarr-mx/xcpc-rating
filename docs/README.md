# docs/ — 项目文档

校内 XCPC 系列编程竞赛的 Rating 统计与展示系统。汇总正式赛（训练赛、OJ 数据规划中），运行时计算选手 Rating，提供可交互的 Web 应用。

> **技术路线（已采纳并落地中）**：Reflex（Python 全栈 Web）+ SQLite + Caddy 反向代理。
> 原 Vue 3 静态站方案已废弃（留 Git 历史）。

## 3. 文档约定

- 文档分三类定位：**参考**（描述已实现的系统，含代码路径，是权威描述）、**待建**（设计已定、代码未写，实现时以此为准）、**指南/计划**。
- 已实现的行为以代码为准；文档与代码不一致时，先修文档。
- 设计文档中的「开放问题」集中在 [08-路线图](08-路线图.md) §4 统一跟踪。
- `data/raw/` 与 `data/db/` 的数据约定见 [01-架构与数据流](01-架构与数据流.md)。

## 4. AI Agent Skills

`skill/` 目录存放 AI Agent 工作流指引（`SKILL.md`），与 docs/（给人看）分离：

| 技能 | 用途 |
|------|------|
| [formal-import](../skill/formal-import/SKILL.md) | 正式赛导入：收集参数 → 预览解析 → 执行导入 → 补录打星队 → 报告 |
| [player-manage](../skill/player-manage/SKILL.md) | 选手名册 CRUD：检查 → 去重 → 执行 → 报告 |
| [team-manage](../skill/team-manage/SKILL.md) | 队伍名册 CRUD：队员集合识别、别名管理 |

Agent 协作要点（提示词要素、边界约定）见 [07-开发流程](07-开发流程.md) §7。技能文件约定：每技能一个子目录一个 `SKILL.md`；禁止在技能中写爬取、子串匹配等不规范操作；CLI/API 路径随包结构同步更新。
