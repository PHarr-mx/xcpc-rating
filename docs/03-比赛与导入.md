# 比赛与导入

> 定位：**参考 + 待建**。关联：[02-选手与队伍](02-选手与队伍.md) · [04-Rating与榜单](04-Rating与榜单.md) · [05-Web与认证](05-Web与认证.md)

定义三类**可计入 Rating 的数据来源**及其结构。**本系统不爬取数据**，只接收人工或外部导出的文件，完成校验、关联选手/队伍、写入 SQLite。

> 实现状态：**正式赛（formal）全链路已实现**；训练赛（training）与 OJ 数据源为**待建**（表结构、DTO 与权重配置已备好，无读写代码）。

---

## 1. 数据类型总览

```
                    ┌─────────────────────────────────────┐
                    │           选手 Rating 输入            │
                    └─────────────────────────────────────┘
         ┌──────────────────┬──────────────────┬──────────────────┐
         ▼                  ▼                  ▼
   ┌───────────┐      ┌───────────┐      ┌───────────────────────┐
   │ 正式比赛   │      │ 校内训练赛 │      │ OJ 记录                │
   │ formal    │      │ training  │      │ ├── oj_contest (比赛)  │
   │  ✅ 已实现 │      │  ⬜ 待建  │      │ └── oj_practice (做题) │
   └───────────┘      └───────────┘      │    ⬜ 待建             │
                                          └───────────────────────┘
```

| 类型 | `source_type` | 计入「仅正式赛榜」 | 计入「全部数据榜」 | 粒度 | 状态 |
|------|---------------|-------------------|-------------------|------|------|
| 正式比赛 | `formal` | ✅ | ✅ | 参赛单元（1–3 人）为主，映射到选手 | ✅ |
| 校内训练赛 | `training` | ❌ | ✅ | 参赛单元或个人排行榜 | ⬜ |
| OJ 比赛 | `oj_contest` | ❌ | ✅ | 选手 + 平台 | ⬜ |
| OJ 做题 | `oj_practice` | ❌ | ✅ | 选手 + 平台 | ⬜ |

存储层 formal 与 training **合一张 `contest` 表**（`source_type` 区分，见 [01](01-架构与数据流.md) §4.2）。

## 2. 正式赛（formal）✅ 已实现

### 2.1 业务规则

- 只保存**校内相关队伍**的：排名、获奖、解题数、罚时等；同时保存全场参赛总队伍数 `total_teams`（含外校，用于难度/权重估计）
- 不保存外校队伍明细；`contest_type` 决定权重（`data/config/contest_weights.yaml` 查表，未登记类型直接报错；支持 `weight_override`）

### 2.2 比赛元信息（`contest` 表）

关键字段：`id`（`{contest_id}`，formal 惯例 `formal_` 前缀或年份_赛事名）、`title`、`date`（由它推导 `competition_year`/`season`）、`contest_type`、`format`（formal 固定 `team_xcpc`）、`total_teams`（必填）、`school_teams_count`、`rated`、`weight`/`weight_source`（config|override）、`source_file`（追溯 `raw/formal/…`）。

### 2.3 导入链路（三种入口，共用同一套 service）

| 入口 | 场景 | 说明 |
|------|------|------|
| **一步式** `import_formal_xcpcio_xlsx(path, FormalImportParams)` | CLI / Agent（skill：formal-import） | 解析 → 匹配 → 建档建队 → 写库 → raw 归档，一气呵成 |
| **手动补队** `add_formal_team(AddFormalTeamParams)` | 补录打星队 | award 必须达奖线，否则报错 |
| **Web 五步 staged** `/admin/import` | 三期投产的主路径 | 见 §2.4 |

`FormalImportParams` 要点：`contest_id`、`date`、`contest_type`（必填，查权重表）、`format`（固定 `team_xcpc`）、`school_organizations`（来自 `school.yaml`，精确匹配过滤本校队伍）、`standings_sheet`/`total_teams_sheet`（xlsx 页签名）、`include_unofficial`。

### 2.4 Web 在线导入五步（`/admin/import`）

```
步骤 1  上传          [选择 .xlsx]  [上传]
步骤 2  填元信息      contest_id / 日期 / contest_type（→ 自动查权重）
步骤 3  解析预览      312 队，本校 8 队，奖牌线自动推算
步骤 4  匹配未识别    「李某某」→ [新建选手 ▼] [p003 李冉曦]
步骤 5  确认写入      [取消]  [确认导入]
```

关键设计（`xcpc_core/importer/staged.py`）：

- **解析结果先落 `ImportBatch`（`status=staged`），确认后才写正式表**——中途关页面不产生半截数据
- 未匹配项由人工逐个决策，替代 `auto_create_players=True` 盲目自动建号
- 确认时**单个事务**写入选手/队伍/比赛（service 层 `commit=False` + 末尾统一 commit），成功后才归档 raw JSON
- 上传文件用安全临时路径，确认/取消/重传时清理；长解析 `@rx.event(background=True)` 不进写事务
- 写 `import.confirm` 审计

API：`stage_formal_xlsx` / `get_import_batch` / `list_import_batches` / `discard_import_batch` / `confirm_import_batch(batch_id, decisions)`。

### 2.5 配套实现

| 文件 | 职责 |
|------|------|
| `xcpcio_xlsx.py` | XCPC.io xlsx 榜单解析（`parse_xcpcio_xlsx`） |
| `awards.py` | 奖牌线推算与获奖分配（formal_medals / percentile 两种阈值源） |
| `weights.py` / `config.py` | 权重表与 school.yaml 读取、赛年/赛季标签 |
| `players.py` | 队员姓名解析与自动建档（`resolve_member_names`） |
| `formal.py` / `formal_store.py` | 一步式导入主流程、raw 归档读写 |

### 2.6 raw 归档

`data/raw/formal/{contest_id}.json` 由导入**写回归档**（可 diff、可进 Git）：含 `contest_id`/`date`/`contest_type`/`weight`/`award_thresholds`/`standings`（每队 `team_id`、`member_names`、`player_ids`、`rank`、`school_rank`、`award`、`solved`、`penalty`、`unofficial`）/`unmatched_players`/`unmatched_teams`。样例：`data/raw/formal/2026_sichuan_provincial.json`。

**重复导入**：同一 `contest_id` 整批替换 standings（最新导入为准）；删除比赛时级联清理 standings 与派生 `ratingevent`。

## 3. 校内训练赛（training）⬜ 待建

> 表结构、`source_type="training"`、`division` 字段、`training_divisions` 权重配置均已备好；缺导入入口、division→weight 加载器与 rating 事件生成接线。

### 3.1 赛制（format）

| `format` | 名称 | 参赛方式 | 成绩字段 |
|----------|------|----------|----------|
| `team_xcpc` | 组队 XCPC | `members` 1–3 人 | `rank`, `solved`, `penalty` |
| `solo_xcpc` | 个人 XCPC | 单人 | `rank`, `solved`, `penalty` |
| `oi` | OI | 单人 | `rank`, `score` |

命名说明：与 `team_xcpc` 对称用 `solo_xcpc`；OI 没有组队赛，直接叫 `oi`。

### 3.2 难度档（division）

| `division` | 名称 | 面向对象 |
|------------|------|----------|
| `div1` | 老队员组 | 已在队、经验丰富 |
| `div2` | 新队员组 | 入队较新或培养中 |
| `div1+2` | 全体队员组 | 不分新老 |
| `div3` | 未入队新生组 | 尚未加入正式队伍 |

- `division` 是**比赛标签**（写在 contest 元信息上），谁可参加由办赛方控制，系统信任 raw 文件不强制校验
- `weight` 由 `division` 查表（`training_divisions`：div1+2=100 / div1=95 / div2=70 / div3=60），与 `format` 无关
- 同一场训练可只开一档，也可拆多场文件（`…_div1.json` / `…_div2.json`）

### 3.3 元信息与成绩

- id 惯例：`training_2026_w12_team_xcpc_div1+2`；元信息与 formal 共列（`division` 替代 `contest_type`）
- 成绩三种形态：组队（team_id + members）、个人 XCPC（单 player，solved+penalty）、OI（单 player，score）
- 原始目录 `data/raw/training/`（现为空）；导入流程：解析 format/division → 校验成绩字段 → 匹配 team_id/player_id → 写入合表

### 3.4 待建清单

1. 导入入口（在线表单或 xlsx/JSON 导入，是否复用 staged 流程待定）
2. `load_training_weight(division)` 加载器
3. rating 事件生成 training 分支（`rating/events.py` 现有占位）
4. raw/training 归档约定
5. 业务前置：**训练赛成绩如何摊到选手**（开放问题，见 08 路线图）

## 5. 统一事件模型（RatingEvent）✅ formal 路径已实现

Rating 计算前，异构记录统一转为 `RatingEvent`（`xcpc_core/rating/events.py`）：

```python
RatingEvent(
    event_id="{contest_id}#{standing_id}#{player_id}",
    source_type="formal",            # formal|training|oj_contest|oj_practice
    date=..., competition_year=..., season=...,
    contest_type=..., contest_format=...,
    player_id=..., team_id=...,
    payload={"rank": 3, "solved": 8, "penalty": 1200, "total_teams": 86, "award": "gold"},
    weight=70,                        # 整数（基准 100），导入阶段查表写入
)
```

- 队伍赛为每名队员生成一条事件（payload 相同、player_id 不同）
- `build_events_from_contests(session)` 当前默认只取 `source_types=("formal",)`；training/OJ 数据源到位后在此扩展
- 派生表 `ratingevent` 可整表重建，非事实来源

## 6. 时间标签：赛年与赛季

每场比赛在导入时由 `date` 推导 `competition_year` 与 `season`（`xcpc_core/utils/calendar.py`）：

- **赛年**：9/1 划分（月≥9 属当年，否则属上一年）
- **赛季**：秋学期（9–1 月）/ 寒假（2 月）/ 春学期（3–6 月）/ 暑假（7–8 月）

榜单侧的完整定义见 [04-Rating与榜单](04-Rating与榜单.md) §6。

## 8. 与「不爬取」的边界

| 做 | 不做 |
|----|------|
| 解析 raw 下人工放置的文件 | 请求 OJ 网站 API |
| 校验、合并、去重 | 定时爬比赛榜单 |
| 写入 SQLite | 运行时拉取外部数据 |

外部系统（办赛平台、OJ 导出脚本）负责把文件放进 `raw/` 或通过 Web 上传。
